# TAC-to-Solidity training learnings

This file is the persistent research log for TAC-to-Solidity training runs. It records evidence-backed learnings, hypotheses, invalidated assumptions, evaluator issues, and next experiments from the five-iteration research loop started after the 300-row Qwen QLoRA results.

## Current verdict

**Model quality issue with previously untrustworthy methodology; no accepted clean full-run result.** Same-row overfits memorized 30/30, but they do not establish heldout or deployed-bytecode recovery. The old 30-row selector-on result (19/30 strict signatures versus 0/30 selector-off) used a local registry capable of reading signatures compiled from the evaluation source; only 7/30 broad selectors and 1/6 historical heldout selectors are in the bundled inference-time map. That ablation is **not evidence of a bytecode-only improvement** until rerun with comparable prompts. The 2026-07-02 raw 31,577-row run's 1,890-row built-in test reported all-fact F1 0.6281 but behavior-only source-fact F1 0.2245; its bytecode-semantic 0.5083 is a source-fact proxy with 0% runtime comparisons, and every fixed gate overlapped its split. Data alignment, prompt provenance, duplicate-body splitting, gate exclusions, and evaluator labeling were corrected in the 2026-09-24 audit, but **no model was retrained or re-evaluated**. The August checkpoint-11500 result remains a 15-row first-N smoke check, and no final artifact for the earlier eval-clean run is available here. Calls, guards, state writes, hallucinations, and full-context deployability remain open.

**Follow-up (2026-09-24, model-free):** A compiler-produced optimized getter lost a reachable RETURN because the CFG inferred a consumed PUSH0 as its jump target; a bounded stack-aware fix restores the edge. Training-absent contract-wide metadata was removed from inference prompts. Invalid dispatcher targets now fail or mark a fallback-only reconstruction partial across shared inference and web. Exact full-contract runtime comparison is available as an opt-in *identity* check on compiler-verified examples, not as a behavioral-equivalence claim. A source-fact parser fix removes false ABI matches for nested mappings and false calls from type casts, so even the derived historical behavior-only F1=0.2245 must be recomputed before comparison. No trained model or large current dataset is present to measure downstream model-quality gains.

**Further checkpoint:** A deterministic solc 0.8.20 source-map benchmark found ABI selectors in all 36 locally compiled functions but reached source-mapped behavior opcodes in only 18/36; the 18 parameterized functions lost decoder-return paths. Bounded stack-context traversal now reaches 36/36, with no selector/CFG failures in this corpus. A separate 30-contract runtime control measured 61 checked (30 exact matches, 31 mismatches) and 60 intentionally unchecked cases; one comment-only change yielded unequal full bytecode while its executable prefix was unchanged. These are model-free *structural and identity* controls, not proof of semantic recovery or a new trained-model result.

**Bounded real-data audit (2026-09-24):** Regenerated 2,000 public verified-contract records locally with the exact cached Qwen tokenizer and source-aligned single-compiler policy. Of 1,027 unique-body candidate rows after other filters, 618 (60.2%) exceeded 8,192 true training tokens and only 409 exported. Rejected prompts had median 50,224 context tokens (max 204,976), mostly parameterized (475/618), despite the small 36-function benchmark's 36/36 source-map witness coverage. The 409-row dataset is an *audit artifact*, not a clean model run or acceptance result. Prioritize compact, behavior-preserving per-function TAC or hierarchical retrieval; do not silently truncate or train only the easy minority and claim broad decompilation quality.

## Durable learnings

1. **The overfit sanity check is necessary and should run without train-time eval.** The earlier 10-row run stopped at epoch 9 because trainer eval enabled early stopping and selected an earlier checkpoint. Disabling train-time eval via `TRAIN_EVAL_STRATEGY=no` allowed the corrected 10-row run to reach 30 epochs and memorize exactly.
2. **All QLoRA scripts should use 4 GPUs by default for these experiments.** `run_train_qwen_qlora_500.sh` already defaulted to `NUM_GPUS=4`; `run_train_qwen_qlora_overfit_sanity_check.sh` was updated to default to `NUM_GPUS=4` and `GLOBAL_BATCH_SIZE=4`.
3. **Prompt truncation is not the current primary failure mode.** The 300-row evals and the 100-row iteration-4 evals reported zero prompt truncation. Iteration 4 prompt diagnostics had heldout prompt tokens mean ~1574 and max ~3243 under an 8192-token context.
4. **Standalone Solidity validity and bytecode deployability understate memorization quality for function fragments.** Exact-match overfit outputs can still fail deployability because the evaluator compiles fragments without required contract state declarations. Treat syntax/deployability as separate from same-row memorization until the harness understands contract context.
5. **The old `function_signature_match` metric was invalid.** It only compared whether both strings contained a function keyword. This falsely gave `function_signature_match_mean=1.0` to outputs with wrong names like `setMaxTxAmount`, `setBaseURI`, or `getReward`. The strict signature metric now compares function name, parameter count/types, and return count/types.
6. **The model can memorize but is not yet learning robust TAC-conditioned generalization.** The corrected 10-row and 30-row overfits show exact same-row fit, while 300-row and 100-row heldout results still generate unrelated but plausible Solidity functions.
7. **Heldout sample counts below 30 are smoke signals.** The 100-row run had only 6 heldout test examples, so its heldout metrics should not be overinterpreted. Its train-row eval is still useful for memorization diagnostics.
8. **Superseded as bytecode-only evidence: selector signatures appeared recoverable from the local registry.** That registry also contained signatures compiled from heldout source; the 0-to-19/30 strict-match ablation cannot establish production-reproducible gains. Recheck with bundled-only or independently sourced signatures (learning 40).
9. **Selector metadata does not solve bytecode-grounded semantics by itself.** The retrained selector-metadata model improved broad-30 replication F1 micro to ~0.595 and signatures to 24/30, but call, storage-write, guard, selector, compiler/deployability, and syntax/scaffold buckets still dominate.
10. **Deployability remains an evaluator/model-context issue for function fragments.** Exact or near-exact train-row outputs still score 0 deployability because function-level snippets are compiled without contract state/context.
11. **`solidity_valid` should mean syntax/scaffold validity for function fragments, not full deployability.** Local solc often reports undeclared identifiers or missing modifiers when a correct function body references contract-level state; those are now classified as context-limited compiler results while `bytecode_deployable` remains false.
12. **Evaluation records need TAC-derived segment metadata.** Without copying derived opcode/control-flow groups into per-row metadata, reports can show opcode/control-flow coverage as unknown even when the TAC input contains enough evidence for segmentation.
13. **Use `eval_repetition_penalty=1.05` for current Qwen QLoRA evals.** On the same 30-row broad split it beat 1.0, 1.10, and 1.15 on replication F1 and bytecode semantic score while improving Solidity-valid rate.
14. **Failure-slice evals are now available and should be used before broad retraining.** The calls and state-write slices show lower F1/bytecode scores than broad-30, making them better short-run targets for curriculum and data fixes.
15. **Deduplicate curriculum rows by `metadata.body_hash`.** The source dataset includes optimizer/config variants of the same Solidity body; curriculum selection now keeps one row per body hash and excludes fixed eval body hashes.
16. **Do not keep curriculum continuations based only on broad-30/calls-23/state-17.** The mixed 10-step run looked slightly positive there but regressed on a separate 64-row non-overlap mixed holdout.
17. **Use paired and suite-level gates before keeping model changes.** The new gate correctly rejects both rejected continuations: calls-only regresses calls/state transfer, and mixed regresses state plus the 64-row holdout despite small broad/calls improvements.
18. **Negative curriculum rows should be selected explicitly, not inferred after training.** The curriculum builder can now require categories such as `call`, `member_call`, or `state_write` to be absent, enabling controlled unsupported-call/invented-state-write tests.
19. **Short negative continuations can lower hallucination buckets without improving gated quality.** The negative-mixed run reduced unsupported calls/invented facts on both negative holdouts but still regressed no-state F1, bytecode score, semantic similarity, and validity.
20. **Negative controls should cap ABI/focus complexity.** The first negative slices selected rows with 11-17 ABI-related focus facts and were dominated by selector/ABI mismatches; `max_focus_facts=5` yields cleaner hallucination probes.
21. **Do not change decode defaults based on simple negative slices.** Lowering max new tokens to 256 had no effect, while repetition penalties 1.10 and 1.15 regressed at least one simple negative control.
22. **Prompt-only grounding hints are unsafe for the current adapter.** An explicit "only include supported facts" instruction reduced unsupported calls but regressed F1, bytecode score, and validity on simple negative controls.
23. **The model hallucinates calls and state writes even on pure negative rows.** On corrected 64 simple rows with no target calls/member calls/state writes, the accepted adapter still produced 74 unsupported calls and 36 invented state writes; the earlier pre-fix count was 30.
24. **Nested mapping assignments must count as state writes.** The extractor now catches writes such as `allowed[msg.sender][spender] = amount`; older no-state and pure-negative artifacts before `results/eval_1782623806.json` undercount state writes.
25. **Larger training runs are justified only as staged, gated scale-up.** The accepted 100-row selector-metadata adapter validates the training path but still fails broad/calls/state gates and pure-negative grounding; scale should progress 300 rows -> 1k+ only after fixed gates and negative controls improve together.
26. **A random 300-row selector-metadata scale-up is not enough.** The 300-row run memorized train-first-30 but failed the suite via broad F1, holdout64 bytecode/validity, and large192 validity regressions; do not run random 1k until data conditioning improves.
27. **The accumulated dataset is big enough for a full run, but duplicate-heavy.** `data/hf_training_dataset.jsonl` has 31,577 rows and 16,759 unique body hashes with full selector/signature coverage; train on a deduplicated or body-balanced view rather than assuming every row is independent signal.
28. **One full body-balanced epoch improves behavior metrics but is not acceptable.** The default full run improved F1/bytecode/semantic on every gate slice and strongly improved pure-negative hallucinations, but it failed suite gates on Solidity-valid regressions and did not memorize train-first-30.
29. **Fixed gates must be excluded from full-run training.** The first full body-balanced split included most gate rows in train/val/test (for example, large192 had 154 train + 34 val + 4 test overlaps), so future full runs must reserve gate body hashes before body balancing.
30. **Raw full-source runs through `run_train_qwen_qlora_500.sh` contaminate fixed gates.** The all-row run included every fixed gate body hash somewhere in train/val/test, with most in train, so a passing gate suite after raw full-source training is diagnostic rather than trustworthy heldout evidence.
31. **Duplicate-heavy raw all-row training did not beat body-balanced full training.** The raw 31,577-row run scored lower than the earlier 16,759-identity body-balanced run on comparable built-in test metrics: F1 0.6281 vs 0.6612, semantic 0.7734 vs 0.7840, and bytecode 0.5083 vs 0.5425.
32. **Do not generate training rows by sweeping multiple compiler versions per source.** The prompt is bytecode-only and compiler metadata is oracle-only, while prior data audits show heavy duplicate bodies; source-aligned single compiler configs avoid reweighting identical Solidity targets and preserve compile budget for unique bodies.
33. **Heuristic export-time length filtering was not tokenizer-accurate; exact filtering is now opt-in.** `_token_count_estimate` under-measured TAC, and a prior export left 2,326/25,507 train rows over the Qwen 8192-token budget. The exporter now uses the training prompt and can count target EOS with `--length-tokenizer` (locally cached); without that flag it records `token_count_method=estimate`. Train-time preflight remains mandatory.
34. **Never run single-process `train.py` with multiple GPUs visible.** Hugging Face Trainer wraps the model in DataParallel, which fails with a device-side `nll_loss` assert (`t >= 0 && t < n_classes`) when unquantized and `CUDA error: an illegal memory access` when quantized, despite labels being verifiably in range. `CUDA_VISIBLE_DEVICES=0` makes the same smoke test pass; multi-GPU must use torchrun/DDP.

35. **A mid-training eval can run on CPU when GPUs are saturated.** With all four RTX 8000s at 42-47 GiB of 48 GiB, a 4-bit 7B eval could not fit without risking an OOM in the live trainer. `CUDA_VISIBLE_DEVICES="" --no-quantization --precision fp32` evaluates on CPU at roughly 28 s/sample for short functions, giving zero-risk directional signal. Staged adapter dirs must also contain the base `config.json`/`tokenizer*` files or preflight aborts with `Unrecognized model in <dir>`.
36. **Checkpoint dirs are LoRA adapters only and are not directly evaluable.** `checkpoint-*/` holds `adapter_config.json` + `adapter_model.safetensors` + optimizer/scheduler state, with no tokenizer or base config; copy the base model's `config.json`, `generation_config.json`, `tokenizer.json`, `tokenizer_config.json`, `vocab.json`, and `merges.txt` alongside the adapter before running `--eval-only`.
37. **`train.py` silently falls back to r=16/alpha=32/dropout=0.1 when LoRA flags are omitted.** The fresh-data run `qwen_qlora_full_fresh_20260801-140727` was launched without `--lora-rank/--lora-alpha/--lora-dropout` and trained at half the intended rank with nonzero dropout, unlike every prior successful run (r=32/alpha=64/dropout=0). Always assert LoRA hyperparameters from `training_input_manifest.json` or `adapter_config.json` after launch rather than trusting the command line.
38. **Identical selectors can be genuinely ambiguous, so selector metadata cannot disambiguate every prompt.** `transferFrom(address,address,uint256)` is selector `0x23b872dd` for both ERC20 and ERC721. On that test row the model emitted memorized OpenZeppelin ERC721 boilerplate (`_isApprovedOrOwner`, `tokenId`, no `returns (bool)`) for an ERC20 target, scoring semantic 0.668 / F1 0.583 / bytecode 0.412. This is prior-collapse on the TAC body, not a selector-coverage gap. Learning 40 further supersedes the earlier assertion that all locally resolved selector metadata is independently available at inference.
39. **Under-generation and truncation are ruled out for this run.** Prompt tokens were 608-1181 against an 8192 window with truncation count 0, and generated tokens ranged 19-114 with no row reaching the 512 cap. Per learning 33's prior, do not spend effort on context-window or decode-budget work for this configuration.
40. **Production selector metadata must not be populated from evaluation-source registries.** A compiled heldout signature for `0x5312ea8e` entered a test prompt before the fix; only 7/30 broad and 1/6 historical heldout selectors are in the bundled map. `src/model_setup.py` now accepts only bundled signatures, and `train.py` records `selector_signature_prompt_policy=bundled_only_v1`; old ablations/baselines without this marker are incomparable.
41. **A selector does not uniquely determine the target Solidity function.** ERC20 and ERC721 `transferFrom(address,address,uint256)` share `0x23b872dd`; the exporter formerly chose the last conflicting body. `match_functions_by_selector` now quarantines conflicting bodies or runtime entries and records ambiguity instead of silently mislabeling rows. Compiler ABI can narrow return types but cannot prove which body produced the runtime.
42. **Direct splitting and runner gate exclusion must recompute normalized body identities.** A stale/missing `metadata.body_hash` previously let equivalent targets cross a direct `train.py` train/test split and evade fixed-gate exclusions. The splitter now groups by output-derived body hash and invalidates old split cache schema; runners exclude all six fixed gates using recomputed bodies and other leakage keys before selecting rows.
43. **The historical bytecode semantic score is not a behavioral-equivalence test.** `src/training_pipeline.py` primarily compares facts extracted from two Solidity strings. In `latest_results.txt`, `bytecode_semantic_checked_mean=1.0` coexisted with `bytecode_runtime_checked_mean=0.0`; 0% runtime match means *not evaluated*. Unchecked rows can no longer score 1, reference bytecode is not recycled as generated runtime, and reports distinguish the source-fact proxy from actual runtime comparisons.
44. **Aggregate F1 hides behavioral failures.** The July 1,890-row report's all-fact F1 was 0.6281, but restricting counts to calls, control flow, events, guards, member calls, returns, and state writes yielded pre-fix F1 0.2245 (1,732 TP, 5,476 FP, 6,488 FN). New reports display behavior-only *source-fact* micro F1, and the paired gate rejects its regression; its historical value needs recomputation after learning 48's parser fix.
45. **Fixed instruction-count limits can silently drop large-contract functions.** A 60-selector synthetic dispatcher lost its last 10 selectors at the old 256-instruction scan cap; `src/bytecode_analyzer.py` now scans to the dispatcher terminator and includes all 60 in per-function TAC. This is a deterministic analyzer fix, not measured model improvement.
46. **One incorrect CFG jump can remove an entire reachable Solidity behavior.** On a solc 0.8.20 optimized getter, the old nearest-PUSH heuristic targeted consumed PUSH0 instead of the destination: `block_0045` omitted `block_004c` and its RETURN. A bounded stack simulation now resolves the real destination and isolates the sibling function; other cross-block dynamic jumps still need a broader fidelity study.
47. **Never turn failed function segmentation into successful source generation.** An invalid selector target (`0x60003560e01c80631234567814602057`) formerly produced a fake `contract` TAC prompt; shared inference, CLI, and web now report `analysis_failed` with no model call. If a real fallback remains, they retain it but report `partial_analysis`, rejected selector/target diagnostics, and unresolved quality instead of claiming full coverage.
48. **The source-fact extractor can overstate both ABI and call recovery.** `function f(mapping(address => uint256) storage ledger)` vs a bool-mapping target previously scored ABI F1=1.0 because a regex stopped at the inner `)` and split `=>` at `=`. Balanced signatures now distinguish types; `bytes32(...)`/`uint8(...)` casts are not calls, and a bodyless declaration does not inherit the next function's body. Recompute old F1 and hallucination buckets before comparing metrics.
49. **Inference metadata must match the trained prompt, not merely be bytecode-derived.** Contract-wide instruction/function counts were being added to every inference function despite being absent from sampled training rows; `src/inference.py` no longer injects them. These facts remain in contract-level analysis and reconstruction diagnostics.
50. **Runtime bytecode equality needs independently verified compiler provenance and explicit coverage.** `metadata.runtime_comparison` opts in complete named reference/generated contracts with installed matching solc settings; the reference source must reproduce the provided runtime before generated code is compared. Record checked n, equal n, skip reasons, and equality among checked rows; 0 checked does not mean 0% match. Exact bytecode identity is not deployment or behavioral equivalence, and unsupported constructor/inheritance/function-fragment contexts stay unchecked.
51. **Parameterized function bodies were systematically absent despite perfect selector recall.** The 36-case compiler-source-map benchmark initially found 36/36 selectors but only 18/36 reachable behavior opcode witnesses: 0/18 parameterized vs 18/18 simple. Bounded stack-context traversal across ABI decoder returns restored all 18 parameterized witnesses without regressing simple cases. A selector or TAC header alone does not establish behavioral input coverage.
52. **Exact runtime equality is too strict to stand in for semantic equivalence.** In 30 full-contract controls, 30 identical candidates were byte-equal and 30 return/storage mutations byte-unequal, but a comment-only source change also produced byte-unequal runtime due to Solidity metadata despite an identical executable prefix. Preserve the exact-byte label and seek independent differential/semantic controls.
53. **Full-run gates must reject stale baselines before expensive training.** The full body-balanced runner now validates all six fixed-gate baseline JSONs for row identities, settings, prompt policy, behavior-only metric and zero truncation before training, rather than failing hours later. `RUN_GATES=0` is a diagnostic override, not an acceptance decision.
54. **Actual-token length is the immediate real-data bottleneck after CFG reachability repair.** In a bounded 2,000-source regeneration, 618/1,027 unique-body candidates (60.2%) exceeded the real Qwen 8,192-token prompt+target cap; rejected prompt median was 50,224 tokens despite target median only 61. Long samples can contain 2,417 TAC instruction lines at the median; 475/618 rejects are parameterized. Do not treat 409 surviving short rows as representative heldout decompilation.

## Hypotheses

1. **High confidence: the 300-row baseline was undertrained for TAC conditioning.** Evidence: it scored poorly even on train rows (`results/eval_1782603004.json`) and emitted repeated unrelated snippets.
2. **High confidence: early stopping can confound overfit sanity checks.** Evidence: the failed 10-row overfit stopped before the requested 30 epochs; the corrected no-train-eval run memorized 10/10.
3. **Medium-high confidence: current data scale/coverage is insufficient for heldout generalization.** Evidence: iteration 4 achieved strong train memorization on many examples but 0/6 strict signature matches on heldout rows, and iteration 5 showed the same pipeline can memorize 30/30 identical train/test rows.
4. **Medium confidence: target/source quality or prompt metadata may be too weak for function identity.** Evidence: the model often generates plausible ABI-compatible Solidity unrelated to the TAC, suggesting it is relying on memorized priors rather than grounding in TAC details.
5. **Medium confidence: more updates help train fit, but alone will overfit without solving generalization.** Evidence: 10 epochs on 83 train rows drove training loss down to ~0.474 overall and final logged losses near 0.01, yet heldout remained poor.
6. **Superseded pending a clean rerun: selector-signature metadata should stay enabled for QLoRA runs.** The broad-30 paired ablation improved semantic similarity by +0.3766 and replication F1 micro by +0.3380, but compiled-source registry access could provide heldout signatures unavailable at deployment. Test bundled-only metadata against selector-off before concluding it helps.
7. **Medium confidence: selector-metadata retraining helps broad generalization modestly, but the current 100-row scale is still too small.** Evidence: broad-30 old-adapter selector-on F1 was ~0.5524, while the selector-metadata retrain reached ~0.5954; exact correctness remained 0/30.
8. **Medium-high confidence: decoding was slightly over-penalizing repetition at 1.15.** Evidence: lowering eval repetition penalty to 1.05 improved broad-30 semantic/edit/F1/bytecode and validity without changing model weights.
9. **High confidence: calls are the first curriculum bottleneck.** Evidence: the calls slice has 43 missing call facts and replication F1 micro 0.5422 under the best decode setting.
10. **Medium confidence: a small calls/state-write curriculum needs negative rows and a strict suite gate to be useful.** Evidence: dense positive-only calls and mixed continuations both regressed at least one required comparison.
11. **Medium confidence: naive continuation from the selector-metadata checkpoint is fragile.** Evidence: both call-only and mixed continuations failed the stronger keep criteria despite low train loss and small local metric movements.
12. **Medium confidence: unsupported extra facts may need explicit negative examples.** Evidence: the rejected continuations either lost recall or regressed transfer; the next cheap path is reducing unsupported calls/invented state writes while preserving the 64-row holdout F1.
13. **Low-medium confidence: negative rows need a better schedule or loss balance before they are useful.** Evidence: 10 extra LR 2e-5 steps improved no-call metrics but regressed no-state metrics and validity.
14. **Medium confidence: unsupported calls are the most robust hallucination target on simple negatives.** Evidence: even after simplifying ABI complexity, simple no-state still has 117 unsupported calls and simple no-call still has 43 unsupported calls.
15. **High confidence: repetition penalty is not the fix for negative hallucinations.** Evidence: 1.15 trades no-call improvement for large no-state regression, and 1.10 regresses both simple controls.
16. **Medium confidence: grounding constraints need to be trained, not only added at inference.** Evidence: an untrained prompt hint changed output distribution but caused correctness regressions and more invented events.
17. **High confidence: pure negative rows are a cleaner hallucination probe than single-category negatives.** Evidence: requiring both no calls and no state writes keeps selector mismatches relatively low while exposing unsupported calls/state writes directly.
18. **High confidence: the call/state hallucination issue survives corrected state-write labels.** Evidence: the rebuilt pure-negative eval still has 74 unsupported calls and 36 invented state writes.
19. **High confidence: behavior-balanced sampling is now a better next path than random scale.** Evidence: the random 300-row run improved some local slices but failed broad/holdout/large gates, while the new fallback curriculum directly covers calls, state writes, guards, returns, events, and pure negatives without overlapping gates.
20. **Medium-high confidence: a full deduplicated/body-balanced run may outperform small random runs.** Evidence: coverage is broad enough across behavior categories, but small random runs likely overfit dominant bodies/boilerplate before learning rare TAC-conditioned semantics.
21. **Medium-high confidence: the full run is under-optimized rather than pipeline-broken.** Evidence: one epoch over 13,635 train rows left train-first-30 at F1 0.6087/bytecode 0.5133 with train loss 0.7058, while prior small overfits can memorize exactly and prompt truncation stayed zero.
22. **High confidence: the first full-run gate gains were not trustworthy heldout gains.** Evidence: the full split overlapped every fixed gate, including 61/64 holdout64 and 154/192 large192 rows in train. The model still underfit many overlapping rows, but those gates can no longer be treated as heldout for that run.
23. **Medium-high confidence: duplicate-heavy raw scale dilutes useful TAC-conditioned signal compared with body balancing.** Evidence: the raw run used all 31,577 rows and 6,431 steps but underperformed the 16,759-row body-balanced run on the built-in heldout test while still failing behavior targets.
24. **High confidence: the raw full-source gate pass is contamination, not clean generalization.** Evidence: all fixed gate body hashes overlapped the raw split, and heavily overlapped slices such as holdout64 achieved very high scores after 63/64 identities landed in train.
25. **High confidence: compiler-version augmentation is lower value than unique-body coverage.** Evidence: the source export had 14,818 duplicate-body rows before body balancing, and the best current full-run path already caps by `metadata.body_hash`; multi-version rows mostly add alternate TAC for the same target body rather than new semantic supervision.
26. **Medium-high confidence: evaluation-source selector lookup inflated at least some previous identity scores.** A regression reproduces a heldout compiled-source signature entering the prompt; only 7/30 broad selectors are bundled. The size of its impact remains unknown without a clean paired rerun.
27. **Medium confidence: clean body-balanced training may still improve source-fact behavior, but prior gates cannot decide acceptance.** Fixed-gate overlap and changed prompt policy invalidate previous gate passes; an eval-clean run with fresh paired baselines is required. The August 15-row CPU smoke was first-N with duplicate targets.
28. **High confidence: improved TAC reachability is a better near-term input-conditioning experiment than increasing context length.** The compiled getter lacked a reachable RETURN while prompt truncation remained zero in historical evals; quantify missing returns/calls/guards across compiler-produced slices before another training scale-up.
29. **Medium confidence: exact runtime checks on a well-selected full-contract slice can calibrate the source-fact proxy.** The opt-in harness differentiates one identical vs one changed-return complete contract, but current function-fragment datasets cannot supply comparable full-context rows without additional ground truth.
30. **High confidence: stack-aware decoder-return tracking improves the available TAC signal on parameterized behavior families.** On one local solc/compiler/optimizer configuration, all 18 parameterized source-map witnesses changed from unreachable to reached; test other compiler versions, loops, and complex contracts before assuming generalized 100% coverage.
31. **High confidence: strict runtime byte equality has metadata-induced false negatives as a semantic proxy.** The comment-only control changes full runtime bytes while leaving executable prefix unchanged. Recompilation with matched source metadata helps distinguish identity from behavior, but cannot replace differential execution.
32. **High confidence: most current unique-body function rows are too long at 8k without loss-aware TAC reduction.** The bounded regenerated corpus's exact tokenizer quarantined 60.2% for context overlength, whereas no target was quarantined for overlength. Unknown whether per-function shared-code inclusion, compiler source diversity, or legitimate complexity dominates; measure block overlap and behavior-witness retention before changing context length.

## Invalidated assumptions

1. **Invalidated: "The pipeline cannot learn at all."** The corrected 10-row and 30-row overfits achieved exact reproduction, and iteration-4 train-first-30 got 21/30 exact matches.
2. **Invalidated: "Function signature match was a reassuring metric."** The old metric was a keyword-presence check and gave false positives; strict recomputation dropped the 300-row train and heldout signature rates to 0/17.
3. **Invalidated: "Poor metrics were caused mainly by under-generation from low `eval_max_new_tokens`."** Later evals used 256-512 generation tokens and still showed unrelated snippets.
4. **Invalidated: "Prompt truncation explains the failures."** Prompt diagnostics repeatedly showed zero truncation.
5. **Invalidated: "Heldout failure alone proves train/eval wiring is broken."** Same-row overfit success shows the basic wiring works; the failure has shifted toward scale, data, and generalization.
6. **Invalidated: "Wrong function names are only a model-capacity problem."** Local selector provenance recovered all tested signatures; exposing that provenance fixed many function identity errors without changing weights.
7. **Invalidated: "A selector-metadata retrain immediately solves heldout behavior."** The 100-row retrain improved train memorization and broad structured metrics, but heldout/broad outputs still miss bytecode behavior and remain non-deployable.
8. **Invalidated: "0% Solidity-valid on exact overfit outputs proves syntax collapse."** The exact 30-row overfit outputs are scaffold-valid; the old metric was penalizing missing contract context from solc, not malformed Solidity.
9. **Invalidated: "A call-dense continuation by itself will fix the calls slice."** The first 48-row calls continuation slightly improved semantic/bytecode scores but reduced replication F1 and recall on the same fixed calls slice, and it regressed state-write transfer.
10. **Invalidated: "A small broad-30/calls-slice improvement is enough to keep a continuation."** The mixed continuation passed those small checks but failed a larger 64-row non-overlap mixed holdout, so it was reverted.
11. **Invalidated: "The default full body-balanced gate suite was cleanly heldout."** The full body-balanced split was built from the same source as the fixed gates and included many gate body hashes; the runner now excludes those identities by default.
12. **Invalidated: "Using all source rows through `run_train_qwen_qlora_500.sh` makes fixed gates trustworthy."** The raw all-row split overlapped 100% of the fixed gate identities, so fixed-gate improvements from that run cannot be treated as heldout evidence.
13. **Invalidated: "Three compiler versions per training point are useful default augmentation."** Current evidence favors source-aligned, body-deduplicated coverage; the generator now treats multi-version expansion as removed rather than a default or recommended path.
14. **Invalidated: "A locally resolved selector is independently available from deployed bytecode."** `contracts.db` contained compiled evaluation-source signatures. Production prompts now admit only bundled signatures, and historical selector-assisted evals need reruns.
15. **Invalidated: "`bytecode_semantic_checked_mean=1` means runtime behavior was compared."** The July report had 100% legacy checked but 0% generated/reference runtime comparisons; the score is primarily source-fact overlap.
16. **Invalidated: "A passing all-fact F1 indicates guards/calls/storage were recovered."** The same July report had all-fact F1 0.6281 but behavior-only source-fact F1 0.2245; inspect category slices and actual runtime coverage.
17. **Invalidated: "All gate exclusions and cached splits were already evaluation-clean."** Missing/stale body hashes and raw sampler cache reuse could leak normalized-equivalent rows; runners and direct splitter now recompute identities and validate provenance.
18. **Invalidated: "A parsed selector necessarily yields recoverable function TAC."** Invalid targets previously fell back to the entire contract and looked model-generated; now missing selectors are rejected and surfaced even if a fallback is valid.
19. **Invalidated: "Bytecode-derived prompt counts are always helpful to add at inference."** Training lacked the contract-wide instruction/function count fields; inference now matches training rather than presenting an untrained distribution.
20. **Invalidated: "Source-extracted call/ABI buckets are reliable for nested types and casts."** The old regex gave a wrong mapping type ABI F1=1 and treated `bytes32(...)` as a call; the corrected extractor requires regenerated baselines.
21. **Invalidated: "Finding all ABI selectors means function TAC contains their behavior."** Before decoder-return repair, 36/36 selectors existed but the 18 parameterized bodies lost compiler-mapped opcodes.
22. **Invalidated: "Exact runtime byte mismatch proves a behavioral difference."** One comment-only source change yielded unequal bytecode because solc appended different source metadata; the executable prefix was unchanged.
23. **Invalidated: "Missing gate baselines can be diagnosed after a full training run."** Post-training rejection wastes GPU time and cannot rescue a contaminated acceptance gate; the runner now checks all baselines first.
24. **Invalidated: "The small synthetic 36/36 TAC benchmark implies real examples fit training context."** On 2,000 independently sourced records, 618 of 1,027 unique-body candidates exceeded 8,192 Qwen tokens despite 36/36 small-function witness coverage. Coverage and trainability must be reported separately.

## Suggestions and next experiments

1. **Run paired train/heldout evals for every future training run.** Success criterion: train strict signature match and replication F1 rise first; heldout should then improve on a comparable split before claiming generalization.
2. **Create data-slice evals by function family and behavior.** Evaluate short getters, setters, transfers, calls, returns, guards, events, and storage writes separately. Success criterion: identify the first capability slice that fails before running larger expensive jobs.
3. **Superseded/rejected: random 300-row staged scale-up.** `models/qwen2_5_coder_7b_qlora_500_loop_iter32_selector_metadata_300/` memorized train rows but failed the gate suite, so do not promote this path to 1k. Success criterion to reopen random scale: a future 300-row random seed must improve broad F1, holdout64 bytecode/validity, pure-negative hallucinations, and large192 validity together.
4. **Build behavior slices now that function identity is partially fixed.** Evaluate short getters/setters, calls, returns, guards, events, and storage writes separately. Success criterion: identify whether calls/storage/guards are first-failing capabilities before another broad run.
5. **Create a failure-bucket curriculum.** Start with simple short getters/setters using selector metadata, then add calls, guards, events, and state writes. Success criterion: heldout strict signature and replication F1 improve within each slice before increasing task diversity.
6. **Improve the deployability/scaffold evaluator for function fragments.** Success criterion: exact-match overfit rows should no longer receive 0% Solidity/deployability solely because contract-level state declarations are absent.
7. **Compare base model vs adapter outputs on selector-signature prompts.** Success criterion: final adapter output should differ materially from base output on train rows and reproduce learned targets; if not, investigate adapter loading or checkpoint selection.
8. **Inspect failure buckets for calls, returns, guards, and state writes.** Success criterion: reduce these buckets and improve replication recall without increasing unsupported extra facts.
9. **Train or evaluate a failure-bucket curriculum before another broad run.** Start with rows dominated by calls/member calls, then state writes, guards, returns, and events. Success criterion: each slice improves replication recall and bytecode semantic score on a heldout slice without increasing unsupported calls/state writes.
10. **Add compiler-version-aware syntax checks for generated fragments.** The remaining 3/30 broad syntax failures are version-related or true syntax issues: missing visibility under solc 0.5.x, `override` under solc 0.5.7, and `payable(...)` syntax under solc 0.5.17. Success criterion: prompts or targets avoid version-incompatible constructs for the target compiler.
